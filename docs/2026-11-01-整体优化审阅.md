# 编译器整体优化审阅

本页面向继续开发编译器的队友。审阅以 `teacher-stable-2026-11-01` 的阶段入口、上下文、文件编辑、IR 校验、运行时与验收实现为依据；实测成本取原版稳定运行。新实验结论归 [实验报告](experiments/2026-11-01-baseline-optimization.md)，不能把下面的候选方向当成已经取得的收益。

## 成本集中在哪里

稳定运行合计 1,271,206 token，90 次模型返回；包含一次 Stage 11 失败后的续跑。按返回 usage 统计：

| 阶段 | 总 token | 占比 | 主要重复 |
| --- | ---: | ---: | --- |
| 12 事件实现与 E2E | 810,462 | 63.8% | 每个 handler 重发整页、所有事件与外部测试；终验重发全量源文件 |
| 11 交互与 P/Q | 147,329 | 11.6% | 每个事件单独推断 P/Q，反复携带需求、绑定和参考测试 |
| 10 页面实现 | 127,688 | 10.0% | 整文件回传，标签/可见性失败导致重复输出页面 |
| 08 后端测试与实现 | 83,194 | 6.5% | 测试生成、独立复核、整文件实现和回归 |
| 其余阶段合计 | 102,533 | 8.1% | 输入分析、schema、义务、SQL、API 与 UI 设计 |

Stage 12 里 18 次非终验创建调用，单次输入约 25k token，包含一行字段更新也承担的页面与其他事件。更换 BM25 检索器、优化 Python 集合操作、减少日志打印都不会直接解决这个量级的模型输入。优先改变上下文供给粒度，再测总量与修复代价。

`scripts/profile_compiler.py` 将 SDK usage、调用类别与请求字符拆开统计。字符重放只改变同一历史请求的输入组装，可隔离“少发了多少文本”，不能推断新模型输出质量或精确 token。

## 第一优先：收窄事件创建，保留完整验收

[当前事件实现](../infrastructure/stages/frontend/interactions/implementation.py) 已有初步瘦身，但仍重复全部 page_subtrees、triggers、events、requirement，以及可写页面源码。试验 `ARC_EVENT_CONTEXT=1` 进一步只给目标事件、完整 P/Q、所有共享触发器、触发源元素、全部前端绑定、相关 API 和路由。最终修复调用继续读取全量页面、handler 与冻结测试；每个新文件仍 typecheck，原浏览器 gate 不变。

不能只根据 event.write 选择绑定：写权限不是读依赖，动作仍是自然语言。也不能在无证明时把 local 动作编译成赋值；它可能包含条件、日期转换、错误处理与早返回。先测上下文收窄，再决定是否值得引入有类型的 action IR。

同一批历史 18 次请求的 payload 字符从 1,545,052 降至 317,544（79.4%）。这个数包括任务和文件部分，不含 system prompt，不能叫总 token 节省。真实完整对照另行报告；终验轮数上升可能抵消输入下降。当前开关默认关闭，稳定路径可直接恢复。

实测已完成，结果归 [对照数据](experiments/event-context-comparison.json)：全新候选总 token 少 23.2%，但外部验收仅 7/14，未通过；相同上游的 Stage 12 试验输入少 62.0%，外部验收首跑 13/14、原样重跑 14/14。10 个匹配创建调用的平均输入少 73.4%，更直接支持上下文下降。开关继续默认关闭；不能从局部收益跳到整体成功率提升。

## 第二优先：减少往返次数，但先明确依赖

[Stage 11](../infrastructure/stages/frontend/interactions/synthesis.py) 先逐叶子分解，再逐事件推断 P/Q；稳定轨迹共 26 次调用。可试同一页面的 P/Q 批量返回，再由现有 validator 逐项检查，并只重试失败项。这能减少重复前缀与网络往返，但批量输出截断、一次错误连带重算需单独记录。输入/checkbox 小事件也可小批创建，必须先扩展单文件创建协议，保留逐目标路径登记及全局终验。

目前 [FileWorkspace](../infrastructure/shared/agent/files.py) 每轮供给和替换整文件。大页面小修复会重发大段代码。未来可增加有内容哈希保护的局部编辑协议；旧整文件协议作为回退，拒绝旧版本补丁、重复匹配和不完整修改。先量化页面重复量，再承担新协议复杂度。

## 第三优先：恢复机制要证明输入和阶段确实匹配

[run_all.py](../run_all.py) 的恢复依据主要是文件存在，存在以下代码级缺口；尚未据此构造真实事故，不把它们写成已发生损坏：

- Stage 02 在每个需求后写 db_schema.json，但恢复看到该文件就跳过整阶段。文件可能只是部分设计。
- Stage 05 只要任一 SQL 存在便算完成，不能证明所有 schema 表都实现。
- Stage 10 不在 GREEN_SENTINELS 中；FAILED 的 ui_checks.json 也满足跳过条件。
- 输入、提示词、模型配置或前置 IR 变化后，没有依赖指纹让后续结果自动失效。

应增加阶段完成记录：输入/前置工件/源码相关文件哈希、配置、输出哈希、完成状态；仅成功发布完成记录，变更沿 DAG 失效。独立于此保留局部 checkpoint 的“可恢复但未完成”状态。验收要包含中途失败、输入变更、输出篡改和真正完成的恢复，不能只检查哨兵文件。

这会增加确定性 bookkeeping，但比过早复用部分工件更可控。作为下一项独立修复实施，不与当前单事件上下文 A/B 混在一起。

## 第四优先：把正确性失败尽早归到正确层

后端单 API 测试通过不代表注册返回的 Cookie 能被会话 API 读取，历史 OPT-F 已有实际反例。冻结 UI 设计前也应核对可见性与外部可访问性契约，避免到 Stage 10/12 才试图修改被错误设计锁定的页面。

当前独立模型复核可拒绝断言矛盾，但与生成使用同一模型且增加调用，不能保证可满足性。可逐步扩展确定性反例检查，并对复核的误拒、漏检与成本独立测量。跨 API 会话组合 smoke 宜在 Stage 08 后执行；测试适配器只连接结构，不修改老师断言。不要遇到跨层失败就允许前端代理修改后端或冻结测试，那会破坏原有责任边界。

新全流程候选把这项优先级进一步坐实：后端/UI/生成 E2E 都 GREEN，老师精确 getByLabel('Password') 却失败。密码类型实际正确，但隐藏的必填星号仍进入标签文本；内部 accessible-name 断言没有替代老师的实际 locator。隔离浏览器反例中该 locator 匹配数为 0，补显式 aria-label 后为 1，未修改候选工件或老师测试。此外 503 会话响应抛为未处理页面异常，固定 F04 拒绝。下一项应把老师真实 locator 与失败语义提前验证，而不是通过改老师测试消除失败。

共享上游的试验还出现第三方 Unsplash 图片未完成加载使 networkidle 超时，原样重跑通过。自动报告不记录为 flaky，但跨两次验收已观察到不稳定；不能只保留第二次通过。生成物应优先使用可归档的本地资源，单独审阅视觉质量，减少不必要的外部网络依赖。

现有 IR validator 不等于提示词约束全集：例如 [UI 校验](../infrastructure/stages/frontend/ui/design.py) 多数检查字段形状，[API 契约校验](../infrastructure/stages/backend/contracts.py) 主要保留 R/W；路由、语义 P/Q、引用与完整业务规则不能仅凭其通过就称为形式证明。扩展确定性校验要逐项有反例与回退，不能悄悄把新增限制当成教师原始要求。[交互运行时](../infrastructure/stages/frontend/interactions/runtime.py) 的 update/api/navigation 主要执行 handler 请求，没有完整检查 event.write 和 actions 授权；因此不能把设计权限列表理解成运行时沙箱。若要保证这一性质，需要单独加入权限校验和跨页面旧请求等反例。

## 第五优先：测完整成本与可靠性

目前 SDK 审计能统计返回 usage 与模型累计请求时间；缺少每次 gate 的独立耗时，无法准确分离 tsc、浏览器启动、npm 安装、构建与日志写入成本。`main.py`、Stage 12 和独立验收有重复构建，08/10/12 有重复依赖安装及浏览器安装检查。先加按执行阶段归属的耗时记录，再考虑按依赖指纹缓存；最终独立验收和生产构建仍必须执行。

同配置重复运行至少记录每次完整通过率、失败阶段、总 token、无缓存输入 token、重试次数、模型时间与真实 wall time。返回总 token 少不等于费用更低：缓存输入与输出计价不同；没有实际价格和供应商账单时不报告金额。并发网络调用共享服务器负载，会干扰 wall time 对照。

不优先做“所有阶段并行”：schema/API/UI 增量设计有状态依赖，文件代理允许跨文件修复，容易产生覆盖和归因问题。先隔离纯只读分析，再考虑并行；不得把安全性未知的并发作为性能收益。

## 实施顺序与完成标准

1. 单事件上下文试验已完成但暂不默认启用：保留默认稳定路径，局部 token 下降与全新候选验收失败分别报告。
2. 优先把老师实际定位方式、503 失败语义和本地资源约束提前检查，同时独立修复阶段完成/失效标记；不将这些改动混入已完成对照。
3. 给 gate 和模型请求统一计时，复核主要成本是否仍在 Stage 12。
4. 再试批量 P/Q、受保护局部编辑与依赖缓存，每次只改一项并保留负结果。
5. 有类型动作 IR、跨 API 组合验收和通用外部控件契约逐步推进；视觉相似度另行审查。

稳定标签表示已有一次可复核行为验收成功；单次成功没有证明任意输入正确，也没有证明无人工续跑的成功率。当前任务先形成有证据的低成本候选和可靠对照，后续按上述优先级维护。
