# 完整运行的配置与记录

这份参考用于启动完整生成、寻找历史运行，以及核对两次结果能否比较。成绩和失败原因由[结果页](results.md)维护，模型与检查入口见[开发指南](development.md#模型配置与运行)。原始应用、配置和调用保存在仓库内 gitignored 的 `work/`，不进入 Git 或提交 ZIP。

## 平台任务材料快照

`work/platform-materials-20261105/README.md` 索引当前下载的 Smoke、Lite、完整 Web Application 材料；官方 ZIP、逐任务 YAML/参考图、测试接口响应和文件哈希均在同目录。页面的 Smoke Competition 实际 ID 是 `first-competition`，不能用另一个 `smoke` 标识的访问结果判断它。Smoke 输入和图片可下载，但五条平台测试没有公开源码；Lite 与完整 Web 的 API 公开测试已单独保存。

每个任务的 `input/` 供生成器读取，`acceptance/` 仅供独立验收；不将后者复制进生成 context。材料快照不是一次生成或评测，不进入 run 成功率。平台 Smoke 的需求与根 `input/` 不同，现有本地十四条验收不能替代平台测试。每次真实运行仍需固定任务材料哈希、源码和预算，按新目录隔离。可得范围、HTTP限制和原始来源以本地 manifest 为准，不把缺失测试记录为空套件通过。

## 每轮需要保存的 setting

配置必须在调用模型前落盘；结束后另写结果。历史字段缺失时记录 unknown，不用今天的默认值补写。

| 类别     | 必须记录的内容                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------- |
| 源码     | 完整 Git SHA、引擎、教师快照 SHA、实际提交 ZIP 及哈希；工作区直跑须保存未提交差异              |
| 输入     | 实际输入路径、requirements 和全部参考资产 SHA-256；保存输入副本与外部断言指纹                  |
| 模型     | 文本/视觉模型、reasoning、单次输出上限、请求超时、SDK 重试；若发生参数兼容降级，以实际请求为准 |
| 整轮预算 | 完整尝试次数、调用次数、已返回总 token、墙钟限制；与单次输出空间分开记录                       |
| 环境     | Python、Node、npm 版本、端口；生成后的依赖锁文件、所用依赖快照或安装配置                       |
| 可追溯性 | 启动命令、时间、包身份、模型审计、阶段报告、冻结测试哈希、退出码与停止原因                     |
| 验收     | 开发/生产分别记录准备探针、十四条是否执行、pass/fail/skip/flaky、应用与断言是否保持原样        |

凭据只从环境或 `.env` 读取，不复制整个环境到清单；环境变量优先。需要区别模型服务时保存脱敏服务标识。请求日志保留实际模型参数，不记录认证请求头。输入中的教师测试与 `acceptance/` 是外部验证材料，不作为生成器的模型 context。

`scripts/run_submission.py` 原生相邻 `.run.json` 只包含包身份、deadline、审计开关和退出状态，不能单独作为完整 setting。新轮次应同时保存 `settings.json`；当前这轮的初始化脚本在运行目录 `launch.py`，它拒绝再次启动同一轮。

## 当前完整生成协议

目标是验证已修复的控件契约、radio 语义和组合门禁，在一次从原始输入开始的生成中能否通过。生成源码固定为 `80f3e8e`；后续文档整理不改变受测 ZIP。该次生成已结束，最终 UI 回归失败，完整成绩见[最新结果](results.md#修正版本完整生成首页未知会话状态回归交付失败)。

| 设置           | 当前轮实际约定                                                         |
| -------------- | ---------------------------------------------------------------------- |
| 引擎与输入     | compiler；根 `input/`，三个认证需求和三张参考图                        |
| 模型           | 文本与视觉均 `deepseek-flash`，reasoning 均 `low`                      |
| 单次输出与超时 | 输出最多 320,000 token，含 reasoning；请求最多 600 秒                  |
| 整轮限制       | 一次完整尝试；最多 80 次调用、2,000,000 已返回 token、5,400 秒         |
| 重试           | SDK 传输重试为 0；流水线既有设计纠正、TDD 修复仍运行，全部计入同一账本 |
| 隔离与审计     | 全新 `application/`；保存模型审计、每阶段输入快照、输入和外部断言副本  |
| 固定验收       | 内部门禁全部 GREEN 后，对同一产物分别运行开发与生产十四条              |

单次输出上限沿用原完整运行设置，避免旧 12,000 输出实验的 reasoning 截断；它不代表实际会消耗这么多。整轮预算在发请求前检查，按已返回 usage 累计；未知或未返回 usage 会阻止后续调用，不当作零成本。该账本不是提供方账单硬上限。到期或失败保留原件，不自动开启第二次完整生成。

## 收尾与比较

先检查 `application.run.json` 的退出原因和 `.arc/compilation.json`，再读后端、UI、E2E 逐层报告，不能仅凭进程退出 0 判成功。冻结测试按原始哈希复核，生成后保留测试、源码、数据库、截图、锁文件和日志。固定验收准备失败时标记“十四条未执行”，不记 0/14，也不记通过。

结束后关闭预算账本，汇总所有调用与已知用量，保存 `result.json`，更新本地运行索引，再将可支持的结论写回[结果页](results.md)和[重构计划](redesign.md)。已有失败或中断结果不被诊断复测覆盖。

比较前核对版本、输入、thinking、输出空间、依赖、验收方式与统计单位。legacy、coding、阶段实验和当前 compiler 不合并算成功率；单次成功只能证明该次产物通过，稳定性需要同版本重复样本。依赖清理或压缩使用[开发指南的证据维护规则](development.md#分支与本地材料)，保留原始可复核材料后再处理。
