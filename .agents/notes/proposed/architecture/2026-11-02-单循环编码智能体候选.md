# Agent Note: 用单循环编码智能体验证替代十三阶段编排

Status: proposed

已在保留 legacy 对照和全部验收强度的前提下，实现一个能按需读代码、局部编辑并运行固定检查的单循环候选，检验跨前后端修复能否降低无效调用与失败成本。课程指南允许自行设计智能体；现有十三阶段是实现选择，不是平台入口要求。

现有读写集合检查与分层权限有工程价值，但没有证明自然语言设计、测试可满足性和跨接口协议正确。实际失败中，前端循环无法修复被冻结的后端协议和测试矛盾。继续增加上游识别与回退调度是可行备选，但会扩大当前编排复杂度，因此先用独立候选验证更简单的整体方案。

候选复用模板、模型传输经验、文件边界、隔离浏览器、进程治理、日志和固定断言；同一个实现循环拥有生成应用的前后端业务源码。输入、冻结测试、检查支持和平台启动约定仍由程序保护。测试准备、冻结与最终回归保留，模型不能自行宣告成功。生成测试仍可能错误；首版以 INVALID_TEST 终止保留证据，不建设自动解冻、测试 DSL 或多智能体。

候选通过 `ARC_AGENT_ENGINE=coding` 显式启用，初始默认 legacy；编号阶段不改语义，两种引擎使用独立输出目录。整体回退使用 legacy 或固定基线提交，不从新目录中恢复旧 checkpoint。此决定目前没有替代或移除既有优化记录；它们仍描述可运行的 legacy 路径。

代价是更大的编辑范围可能引入回归，需要可靠的局部编辑、完整检查与日志。旧固定验收依赖阶段 IR，必须用薄适配证明断言与评估等价，不能伪造旧 IR 或 GREEN 报告。历史主实验 3/12 成功与两次 V2 失败只能定位旧路径的问题，不能证明新候选优于旧架构。

验收顺序为零付费工具反例、同一应用上的评估正负控制、假模型跨层修复与预算闭环、空目录上传包验证，再进行固定次数的同期 A/B 与非登录任务验证。工具、循环、评估等价与上传包已经实现并通过离线验证；用户已授权固定次数的付费实验。同期对照、确认实验与回退恢复尚未完成，因此维持 proposed，默认仍为 legacy。[实施计划](../../../../docs/2026-11-02-简洁编码智能体实施计划.md)维护模块、复用和版本边界，[实验计划](../../../../docs/experiments/2026-11-02-编码智能体候选验证计划.md)维护样本、预算、统计和晋升条件。
