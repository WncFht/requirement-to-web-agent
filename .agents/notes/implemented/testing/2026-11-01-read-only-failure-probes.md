# Agent Note: 只读页面加载错误提前检查

Status: implemented

Stage 12 对已实现、由 mount 触发且全部 API 为只读 GET 的处理器执行隔离故障探针：分别返回 503 和拒绝 API promise，若实际处理器抛出异常则要求源码修复。Stage 11 的契约和 Stage 12 的实现提示明确区分可预期读取/传输失败与程序错误，前者必须在处理器内部清除旧身份、更新设计状态并返回，不能清理后再次抛给页面。

选择隔离处理器检查是为了在每个文件创建后及时发现已复现的失败，避免等全部事件完成才被外部 F04 拒绝。它只替换 context.api，不发真实请求、不改生产运行时、不吞掉全局异常，不修改冻结测试。现有类型、E2E、UI 回归与最终构建全部保留；固定 F04 仍用真实浏览器检查身份和数据库边界。

探针只证明默认数据下执行到的路径没有未处理异常，不验证全部前端状态、所有分支或数据库效果。未执行 API 的分支显式报告 NOT_EXERCISED，不计为已覆盖，也不凭此否定有业务条件的处理器。真实浏览器验收仍不可省略。ARC_LEGACY_READ_FAILURES=1 恢复原提示并不运行新探针，不关闭浏览器错误上报。

单元测试直接运行生成的 JavaScript 探针，覆盖已知抛出反例、正确处理、程序错误、未覆盖与选择范围；历史失败模块回放及完整生成结果归实验报告。故障探针会增加少量本地 Node 进程开销，不把它称为性能优化。
