# Agent Note: 场景冻结前核对会话 Cookie 传输

Status: implemented

冻结前的 Cookie 证据来自通过后端阶段的真实响应：在临时副本中运行原后端断言，仅包装副本的编译器测试绑定来捕获成功响应的 Set-Cookie，再由 Chromium 保存这些响应。原应用、原测试及生产数据库不改写。报告只保存 Cookie 名、计数和源文件哈希，不保存凭据；后端源/测试、契约或 Node 版本变化使证据失效。

空字符串表示浏览器实际保存的空名称，空列表表示没有观察到 Cookie，不能混同。E2E 生成上下文供给此证据，既有字面量检查保留；生成阶段的浏览器 fixture 额外检查实际 addCookies 参数，覆盖变量和 helper 设置。明确 valid/existing/seeded/authenticated session/cookie 的正向测试必须至少有一个名称匹配，未知证据时应通过真实注册/登录建立会话。负向 unknown/invalid 等场景不受此正向检查限制。该检查只在冻结前开启；冻结后的原类型、RED/GREEN、UI/E2E 回归与最终构建全部保留。

选择实测而非猜测源码，是因为静态 producer 提取漏掉了真实可用的空名称 Cookie。旧计时反例中，后端浏览器注册/读取正常，但生成测试把凭据同时当名称和值，冻结后前端无法合法修复。此决定不增加“所有 Cookie 必须具名”的教师约束。默认固定验收适配器复用同一实测证据自动连接 Cookie 名，老师原文件和固定断言不变。

ARC_LEGACY_COOKIE_TRANSPORT=1 回退静态证据和旧准入，ARC_LEGACY_E2E_COOKIE_NAMES=1 继续回退名称准入；后者不关闭证据采集。代价是首次增加一次隔离后端测试与 Chromium 检查，相同后端哈希复用结果。当前检查受英文正向标题、测试是否使用编译器 fixture 以及后端测试实际执行的 Cookie producer 覆盖范围限制；多个 Cookie 只证明至少一个匹配，不证明凭据与数据库关系正确。不能称为完整 Cookie 协议证明或测试可信沙箱。

历史反例在新隔离目录中重放：实测空名，错误字面量及动态名称均在冻结前被拒；仅在重放副本把测试设置改为实际空名后，原五个场景全部通过，原冻结套件未改动。单元测试覆盖源与断言不变、证据缓存/失效、未知与空名、失败拒绝、回退及实际 JavaScript guard。完整生成与缓存实验记录放在对应 work 目录，不更新交接材料。
