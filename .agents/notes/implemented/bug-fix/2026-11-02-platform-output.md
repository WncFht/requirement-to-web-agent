# Agent Note: 平台预置目录与可信运行记录分离

Status: implemented

平台入口接受已有模板的初始输出目录，在独立工作区执行原生成流程，完整成功后交付到指定根目录；已存在的编译记录仍拒绝覆盖。这样满足课程传入输出目录的约定，代价是额外的工作区、依赖复制和原文件备份。

课程 PDF 要求将前后端与 deploy.sh 写到传入目录，没有保证目录为空。平台日志中的 /workspace/template 已有文件，旧版在 Stage 00 前就因无可信记录拒绝，原 coding 的新目录限制也有同类问题。此前只用空目录验证上传包，漏掉了实际宿主条件。

不通过放松旧 PipelineState 接纳目录，不把任意旧工作区认作成功或 checkpoint；也不把平台模板覆盖到生成器假设的代码上。入口识别已有编译状态/IR 后保持拒绝，初始非空目录则隔离生成。预装 node_modules 复制而不软链，避免 npm 在失败时修改原目录；新安装、检查和预算照常执行。

成功发布保留目标目录本身及 .git，其他初始内容移至临时工作区的 previous-output，再把完整生成物放在平台指定根层，避免封存后混入未知文件使审计失效。移动失败时回滚已发布项和原文件；生成失败保留原模板和失败工作区。并发发布使用排他标记，强制终止留下锁时需核对进程再处理，不能自动覆盖。备份与诊断依赖运行容器保留时间，不保证平台任务销毁后仍可下载。

当前上游和 coding 的原生门禁、冻结测试和独立断言保持强度。回归覆盖预置模板、两个引擎入口、原目录与失败证据保留、发布回滚、依赖不共享、旧记录拒绝和并发锁。实际 ZIP 启动检查在模型客户端创建前强制停止；coding 另用本地假服务验证全流程、交付后审计、PORT 与图片资源。没有真实模型或平台成功成绩，未知的后续业务错误仍需另行诊断。操作见[打包说明](../../../../docs/submission.md)。
