# Agent Note: 可信恢复与所属进程治理

Status: implemented

legacy 只复用成功子进程和阶段完成条件共同证明的连续前缀，使用整体工作区哈希；输入、编译器或关键配置改变时拒绝复用并保留原目录。中断只清理所属进程树，避免污染下一次运行。代价是没有跨版本的最小 DAG 恢复，也不能提供容器级隔离。

旧文件存在性检查会把部分 schema、任一 SQL 或失败报告误当成功。提高个别哨兵覆盖仍不能证明子进程退出，因此当前移除哨兵路径，不补写或接纳旧完成记录。局部 checkpoint 与完成证明分离；后续合法阶段会修改前面的页面，不能永久拿阶段旧页面哈希判断外部编辑。

普通失败或正常中断封存当前工作区，未通过阶段不进入完成前缀；强制终止未封存时拒绝自动信任。锁只协调受管流水线，不阻止外部编辑器、单阶段脚本或其他程序。API Key 不参与身份也不写入状态；配置只保存指纹。相比自动删除下游 IR/源码，保守拒绝保留用户编辑与失败证据，不猜测跨阶段文件所有权。

POSIX 在终止父进程前通过 PID/PPID 快照记录后代，清理原进程组和可能另建 session 的实际后代，不按端口、node 名称或路径批量杀进程。缺少 ps 时仍清理原组，Windows 用 taskkill /T。快照后新建并立即被重新托管的守护进程可能逃逸，这不是完整沙箱。

测试覆盖各阶段失败、正常/强制中断、并发锁、输入/源码/配置/产物变更、凭据轮换、合法下游编辑和实际 Stage 00。真实进程反例检查后台心跳停止且无关同类进程继续。操作见[开发指南](../../../../docs/development.md#可信续跑)；没有从这些检查推断模型成功率或速度收益。
