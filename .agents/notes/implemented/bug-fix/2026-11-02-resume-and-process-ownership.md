# Agent Note: 当前运行不复用旧 checkpoint

Status: implemented

当前 upstream 和 coding 要求新生成工作区，已有编译记录拒绝覆盖，不迁移旧 legacy 的可信续跑状态。进程清理只针对自己启动的任务。选择新工作区保留版本边界，代价是没有跨版本或同次自动续跑。

旧 legacy 曾用子进程成功、完成边界和整体工作区指纹保护连续阶段前缀，避免把部分 schema、任一 SQL 或失败报告当成成功。它仍有保留失败证据和不猜测文件所有权的价值，但其状态结构不属于上游 Compiler，也不属于 coding。默认路线替换后不通过伪造记录或旧哨兵兼容它，完整机制与实验留在历史提交和本地归档；未来恢复需显式定义所有权与版本协议。

外层为预置模板建立独立工作区，不把初始非空目录当成旧 checkpoint；平台交付的决定见[目录适配](2026-11-02-platform-output.md)。锁只协调受管发布，不阻止外部编辑器或其他程序。强制终止可能留下锁和未封存工件，需先核对进程，不能自动删除转绿。

POSIX 停止所属任务前记录实际后代，再清理原进程组及另建 session 的后代；不按端口、node 名或路径批量杀进程。Windows 保留 taskkill /T。快照后立即重新托管的守护进程可能逃逸，因此这不是完整安全沙箱。

真实进程回归保留所属后台服务停止、无关同类服务继续；上游原进程工具留在快照，外层治理不改写它的实现。没有从进程与目录检查推断模型可靠性或速度收益，操作见[开发指南](../../../../docs/development.md)。
