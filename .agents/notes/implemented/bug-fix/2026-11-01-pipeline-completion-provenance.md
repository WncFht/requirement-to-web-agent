# Agent Note: 阶段完成记录与保守依赖失效

Status: implemented

流水线只复用有成功退出和阶段完成条件证明的连续前缀，完成记录与局部 checkpoint 分开持久化；输入、编译器、关键配置或工作区改变时整条复用链失效并要求新目录，代价是跨版本的安全局部复用尚不可用。

旧方案把 Stage 02 的部分 schema、Stage 05 的任一 SQL 和 Stage 10 的失败报告当作完整结果。提高单个哨兵的覆盖不能证明程序成功退出，也不能阻止新输入读取旧的 UI checkpoint。因此保留所有阶段原 gate，并在成功子进程后附加完成边界检查；不补写、接纳或修改旧实验的完成记录。[原恢复/重试决策](../process/2026-11-01-pipeline-resume-and-transport-retry.md)中哨兵部分被取代，传输重试与同条件局部恢复继续保留。

整体工作区封存，而非按阶段永久冻结页面哈希，因为 Stage 12 会合法修改 Stage 10 生成的页面。同条件失败或正常中断只封存局部文件，未通过阶段不进入完成前缀；强制终止没有机会封存时拒绝自动信任，并要求新目录。排他锁只协调受管流水线，不承诺阻止单阶段脚本、独立验收或外部编辑器并发写入。API key 不进入配置指纹，状态不写配置原值。

相比自动删除下游 IR/源码，这一版保守拒绝能够保留原证据和用户编辑，不需要猜测共享源码、已冻结测试与局部 checkpoint 的所有权。更细粒度 DAG 失效仍待阶段所有权和迁移协议定义。`ARC_LEGACY_PIPELINE_RESUME=1` 只为显式继续旧实验恢复旧行为，不产生可信记录，也保留已知误判风险。

测试覆盖每个阶段失败后重入、正常中断清理、强制终止状态、并发锁、输入/源码/配置/产物变更、凭据轮换、旧状态拒绝、空设计及下游合法页面修改；另有真实子进程流程与实际 Stage 00。已验收旧产物通过全部完成边界的只读检查，未被接纳为新运行。[验证记录](../../../../docs/experiments/pipeline-resume-validation.json)区分确定性检查与全新模型生成；本改动没有新增完整模型生成或固定外部验收，不升级既有老师稳定标签，也没有 token/速度收益结论。当前接口和恢复操作归[开发指南](../../../../docs/development.md#可信断点续跑与旧目录迁移)。
