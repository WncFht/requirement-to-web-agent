# Agent Note: 保留两种引擎与统一交付接口

Status: implemented

legacy 保留分阶段设计与受限修复，coding 作为独立候选提供跨前后端的同一编码循环，默认仍为 legacy。选择并存是为了保留可复查的开发路径；coding 的实现完成不等于替代方案的效果验证完成。

分层读写集合、契约与文件权限有定位价值，但未证明自然语言设计、测试可满足性或跨接口协议正确。前端无法修复已冻结的错误后端协议，是尝试整体循环的原因。继续增加上游识别和自动回退也是可行方案，但会扩大编排复杂度。coding 复用模板、模型连接、文件边界、进程和真实检查，不复用多层 UI/事件 IR、逐事件循环、RAG、多智能体或自动解冻。

同一实现循环可改整个前后端业务代码，输入、冻结测试和运行支持由程序保护。更大的修改范围可能引入回归，因此保留哈希/片段编辑、原子回滚、完整检查与原始日志。冻结后测试错误以失败结束，不靠改期望修绿。

两套引擎使用同一平台入口和新输出目录，不能混用 checkpoint。独立评估器位于开发工具侧，映射实际 schema 与会话交付后原字节执行固定断言，不伪造旧 IR 或成功报告。旧行为使用 Git 标签恢复，当前运行不携带历史 opt-out；只有打包器识别历史目录布局。

离线工具反例、模拟跨层修复、评估正负控制与上传包接口已有验证；同期比较中断，确认、真实模型泛化与视觉验收未完成。用户已停止真实模型 API，不据此晋升默认或宣称稳定成本收益。当前结构与证据归[架构](../../../../docs/architecture.md)和[结果摘要](../../../../docs/results.md)。
