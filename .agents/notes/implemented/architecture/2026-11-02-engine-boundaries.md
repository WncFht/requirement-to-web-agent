# Agent Note: 教师上游与 coding 分别维护

Status: implemented

默认路线采用固定教师上游快照，coding 保留独立循环及原检查依赖。教师源码在自己的解释器中运行，避免用同名模块覆盖候选，代价是保留少量重复的模板与基础检查代码。

此前旧 legacy 从 Canvas 基线持续派生，却没有同步上游，API 契约和交互 IR 已不同。继续逐项模仿会扩大差异维护面，因此改为整体固定上游，不再保留旧调度和提示词补丁。原本“本地 legacy 为默认”的选择被用户要求替代，旧实现与证据留在提交 `a58ebed`，不伪装成当前教师路线。

上游仍负责十三阶段、提案恢复、源码上下文、triggers、模型配置与部署模板；平台层只选择引擎、管理输出和进程、核对最终成功。没有将上游的独立任务继续策略改成候选循环，也不把上游完成但有失败的报告当作 GREEN。来源、小修正和验证归[上游导入决策](2026-11-02-pinned-upstream.md)。

coding 继续在同一循环修改整个前后端，复用自身保留的模板、文件边界和固定检查，不复用上游 Compiler、UI/triggers IR 或自动解冻。support 是原候选的模块闭包，只有 Python 导入命名空间变化，模板原字节不变；代价是以后升级这些依赖要单独验证，不能自动跟随教师更新。

更大编辑范围可能引入回归，单循环更少模块也不能推出更低成本。冻结测试、预算、哈希编辑、原始日志与独立验收仍保留；同期比较、确认和真实模型泛化未完成；真实 API 仅在明确授权轮次内执行。结构与证据归[架构](../../../../docs/architecture.md)和[结果摘要](../../../../docs/results.md)。
