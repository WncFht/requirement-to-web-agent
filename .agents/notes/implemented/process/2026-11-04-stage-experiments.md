# Agent Note: 阶段回放与完整生成分开归属

Status: implemented

完整生成每次消耗约五十万 token，却难以区分某个 context 修改是否影响当前任务。采用精确请求回放、单页实现和命名阶段快照三种局部实验，结果与完整生成分开归属；代价是实验入口和前置条件需要独立维护，局部成功不能证明组合交付。

历史审计中的一次请求可在新目录重放，原请求与只增加需求契约的请求保持其他参数一致。显式修复再增加真实准入反馈，单独记账，不并入原配对比较。单页实现使用已通过的设计、新脚手架和原生浏览器/类型/构建门禁。所有请求与返回保持原样，源码内容哈希和输入身份随实验保存；已有目录拒绝覆盖。

以后在阶段开始前保存源码与 .arc JSON 的完整文件集哈希，排除数据库、依赖和凭据。窗口仅接受与起始阶段对应的命名快照，恢复时清除旧成功报告，不绕过冻结文件；手工选取的最终状态只能作诊断副本。这样避免用后来修好的源码冒充历史阶段输入。与[不承诺旧续跑](../bug-fix/2026-11-02-resume-and-process-ownership.md)一致，阶段快照也不是可信自动续跑或容器沙箱。

真实实验共享一个串行账本，记录调用预留、返回 usage、截止时间及输出上限。未知 usage、已关闭账本与额度不足均拒绝继续；实验传输关闭自动重试。上次已知输入加本次输出用于保守余量检查，但输入变化仍可能造成一个在途调用的超额，不能称为账单硬上限。正常生成的 SDK 行为保持独立。

已有验证包括快照篡改拒绝、旧 GREEN 不迁入、无 UI 阶段零调用、预算与权限正负例，以及实际五次模型调用。设计在准入反馈后通过，但整页实现两次将全部输出额度用于 reasoning，未生成代码；阶段组合与完整生成因此未执行，不能删去这项验收缺口。结果与后续优先级归[结果摘要](../../../../docs/results.md)，接口归[开发指南](../../../../docs/development.md)。
