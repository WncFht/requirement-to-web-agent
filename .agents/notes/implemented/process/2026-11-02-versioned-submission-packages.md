# Agent Note: 交付身份由提交与引擎共同确定

Status: implemented

打包只读取指定 Git 提交，原平台入口保存在包中，由薄入口固定 upstream/coding 并补默认模型名。每条路线只打包自身运行依赖，本地 make 生成执行同一份包，避免版本名与实际代码不一致。代价是未提交改动必须先提交才能交付。

upstream 包包含固定教师运行源码、模板、13 个入口及来源记录，coding 包包含独立核心和 support；共同包含平台 runtime。开发测试、教师输入、文档、完整上游示例和秘密配置不进 ZIP，根依赖声明是两条路线的依赖合集。原始平台 main.py 保存在 _agent_main.py，逐文件与 ZIP 哈希存外部清单。

平台只保证 URL/Key，旧客户端还需要 MODEL，因此包装器补模型名但不覆盖连接凭据。当前入口不使用重复 engine.json；宿主 ARC_AGENT_ENGINE 不能改变已打包引擎。上游补丁和基线不自动决定某次模型请求成功，也不能把重新包装的历史源码当作已有平台成绩。

历史 legacy/coding 仅由打包器识别旧布局；当前入口没有 legacy 别名和旧驱动。v3 清单独立于旧包，旧 ZIP 不覆盖，原标签不移动。新输出和相邻身份清单保留每次 make run 的来源；平台目录交付由[目录适配](../bug-fix/2026-11-02-platform-output.md)负责，失败保留工件。

测试覆盖现代两引擎隔离、历史布局、未提交文件排除、确定性、环境传递、原入口字节、拒绝覆盖和不安全路径。实际 ZIP 还须做阻断模型的启动验证或本地假服务完整模拟；静态哈希不证明真实任务成功。契约见[打包范围](../../../../docs/packaging.md)。
