# Agent Note: 按提交与引擎确定上传包

Status: implemented

上传包直接读取指定 Git 提交的运行源码，并固定所选引擎；原入口保存在包内，由薄入口提供模型名默认值和引擎选择。这样可以在唯一 main 工作区交付历史版本，代价是新增入口适配层，且未提交修改必须先提交才能交付。

此前只从当前 HEAD 打包单循环，手动切换旧分支、复制目录或依赖宿主 ARC_AGENT_ENGINE 容易让提交名与实际运行不同。现在标签仍指向原提交，旧版编号脚本不迁移；当前源码将这些入口归入 legacy。打包分别识别两种布局，逐文件记录原源码哈希与包内哈希。旧 MODEL 必填客户端只得到默认模型名，平台注入的 URL 和 Key 不被包装器覆盖，也不打包本地配置。

不直接压缩整个源码目录，是为了避免混入模型配置、生成应用或独立验收材料；不修改历史 main.py 字节，是为了保留可核对的原始来源。适配层属于新的交付行为，历史应用验证不自动认证重新打包后的平台成绩，既有 ZIP 与标签均不覆盖。

Make 的本地生成入口执行同一份提交包，用全新输出目录和相邻运行清单记录来源，避免“本地测了未提交源码却上传另一版”。临时源码退出后删除，原 ZIP、清单与失败输出保留。可信续跑继续由直接源码入口负责，不能跨提交或引擎复用旧完成记录。

离线测试覆盖历史与当前目录、未提交改动隔离、确定性打包、拒绝覆盖、原入口身份、凭据环境传递、固定引擎、缺失阶段及不安全文件；迁移后的真实 Stage 00 与源码变化拒绝续跑也有回归。操作与验证范围见[提交指南](../../../../docs/submission.md)。真实模型与网站任务保持停用，不用静态打包通过证明应用生成成功率。
